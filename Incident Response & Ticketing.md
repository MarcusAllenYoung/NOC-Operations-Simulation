# 04 | Incident Response & Ticketing 🎫

Operating the Carolina Crest Bank network as a monitored site and responding to simulated network incidents through detection, troubleshooting, recovery, and ticket closure.

## 1. Purpose & Objectives 🎯

The purpose of this phase is to use the network and monitoring environment built in the previous phases to practice junior / Tier 1 NOC incident response.

Network incidents are intentionally introduced at Carolina Crest Bank - Branch 01 and worked through from the Vertex Network Solutions NOC using LibreNMS, Cisco IOS, endpoint testing, and Spiceworks.

### 🛠️ Tools Used

| **Tool / Platform** | **Role** |
|---|---|
| LibreNMS | Network monitoring, alert detection, and recovery validation |
| Spiceworks Cloud Help Desk | Incident ticket creation, updates, and closure |
| Cisco Catalyst 2960 | SW-01 access switch |
| Cisco ISR 2911 | RTR-01 branch router |
| Windows PC | NOCSVR-01 |
| Windows PC | BRANCH-PC1 endpoint testing |

### 🔗 Objective

- Respond to network alerts generated by LibreNMS
- Create and maintain incident tickets in Spiceworks
- Determine incident scope and service impact
- Perform initial Tier 1 network troubleshooting
- Use Cisco IOS to investigate device and interface state
- Coordinate physical troubleshooting with an onsite contact
- Escalate incidents when required
- Validate service restoration before ticket closure
- Document troubleshooting actions and results
- Return the site to proactive monitoring

## 2. Configurations ⚙️

LibreNMS and Spiceworks were used together to create an operational incident-management workflow.

LibreNMS provides network visibility and alerts, while Spiceworks is used to maintain the incident record from initial detection through resolution.

### 📡 LibreNMS

LibreNMS monitors the network devices and interfaces used throughout the simulation.

Monitored devices include:

- **RTR-01**
- **SW-01**
- SW-01 access and uplink interfaces
- Device availability and interface status

Alerts are used as the starting point for simulated NOC incidents.

### 🎫 Spiceworks

Spiceworks Cloud Help Desk is used to document each incident.

Tickets include:

- Client and site information
- Severity and priority
- Equipment in alarm
- Initial alert information
- Current troubleshooting actions
- Findings and assessments
- Onsite coordination
- Resolution
- Service validation
- Ticket closure

### 🚨 Severity Model

| **Severity** | **Impact** |
|---|---|
| Sev 1 | Critical or widespread outage affecting multiple sites or major services |
| Sev 2 | Complete outage affecting a branch or major site service |
| Sev 3 | Localized outage affecting a single endpoint or service |
| Sev 4 | Minor issue with little or no immediate service impact |

## 3. Validation & Troubleshooting 🔎

### 🔌 Incident 01 — BRANCH-PC1 Network Connectivity Incident

**Severity:** Sev 3  
**Status:** Resolved

LibreNMS generated a critical port-status alert associated with SW-01.

Initial dashboard checks confirmed:

- RTR-01 remained online
- SW-01 remained online
- The branch uplink remained operational
- Gi1/0/10 was down

Remote troubleshooting was performed by SSHing into SW-01.

The following commands were used:

```text
show interfaces status
show interfaces gi1/0/10
show running-config interface gi1/0/10
```

The investigation confirmed:

- Gi1/0/1 remained connected
- Gi1/0/10 was down/down (notconnect)
- Gi1/0/10 was mapped to BRANCH_PC1
- Gi1/0/10 remained correctly configured as an access port in VLAN 10

The issue was isolated to BRANCH-PC1 or its physical Ethernet connection.

### 📞 Onsite Troubleshooting

The onsite contact, Alex Carter, was engaged for Tier 1 troubleshooting.

The endpoint was confirmed powered on and the Ethernet connection was checked.

The Ethernet cable was found disconnected / not fully seated and was reseated.

### ✅ Service Validation

After restoring the connection:

- Gi1/0/10 returned to connected
- LibreNMS cleared the active alert
- SW-01 remained online
- BRANCH-PC1 successfully reached its default gateway
- BRANCH-PC1 successfully reached `8.8.8.8`
- DNS resolution was verified with `google.com`
- Validation testing showed 0% packet loss

The Spiceworks ticket was then closed and the site was returned to proactive monitoring.

## 4. Results & Handoff 🏁

The Incident Response & Ticketing phase converted the LBR-001 network from a monitored lab environment into an operational NOC simulation.

Incident 01 demonstrated the complete incident lifecycle from LibreNMS alert detection through dashboard review, Cisco IOS troubleshooting, onsite coordination, physical fault resolution, service validation, and Spiceworks ticket closure.

The incident also reinforced the importance of determining what remains operational before making changes. Because RTR-01, SW-01, and the branch uplink remained healthy, troubleshooting was narrowed to the BRANCH-PC1 access connection without making unnecessary changes to upstream devices.

With the first incident successfully completed, the next scenario will focus on a branch-wide WAN outage and simulated ISP escalation.
